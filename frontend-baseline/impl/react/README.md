# React port

React 19.3 on Vite 8, React Compiler off, StrictMode on. Same mock API, same public assets and the same stylesheet as the baseline (through the `@baseline` alias), same element ids, so the baseline's checks and measurement script run against this build unchanged.

```sh
cd impl/react
pnpm install
pnpm dev                     # http://localhost:5173 with the mock API
pnpm build && pnpm preview   # the production build
```

From the project root, `pnpm compare --only react` rebuilds this port, opens its pages, runs the flows its pages support and the on-page measurements, and refreshes `docs/results.md` with this column next to the baseline's and the other ports'. The baseline's `tools/smoke` scripts also run against it directly, since the URLs and element ids are the same.

## Ported so far

Patterns 1 to 4 light and patterns 3, 4, 6 and 10 heavy: `static/light.html`, `forms/light.html`, `dynamic/light.html`, `dynamic/heavy.html`, `state/light.html`, `state/heavy.html`, `realtime/heavy.html`, `table/heavy.html`, plus a hub. Links to pages that are not ported lead nowhere in this build; the posts app's "New post" route sends you to the baseline's login page, which this build does not have, so sign in on the baseline first (`pnpm preview` at the project root) when you want to try publishing.

## What React decided for me

- Client rendering. With Vite alone every page is an empty `<div>` until 67 kB of framework has run; the light pages' reason to exist (zero JS, HTML in the response) is gone unless a meta-framework or prerendering is added. That is the first thing a React survey has to price in.
- Keyed reconciliation. The board's 606-card re-render is faster than the baseline's naive rebuild without any work on my part, and the filter keystroke too.
- StrictMode runs effects twice in development, so the fetch in the dynamic page needs its AbortController from day one.
- Controlled inputs for the to-do form and the filter, uncontrolled ones everywhere a native form does the job.
- The grid: the window is computed during render from scroll state that one `requestAnimationFrame` per frame updates, rows are keyed by position so scrolling rewrites cells, the query is an effect over rows, sort, filter and compute whose answer comes back through state, and the two large arrays are plain state replaced whole. The worker does the sorting, so React's share is a 30-row window in 1 to 3 ms, the same as the other three.
- The posts app is React Router (hash history, `useSearchParams`) plus TanStack Query: the cache, the stale time, `keepPreviousData` while a search refines, prefetch on hover, the dependent related query and the optimistic like with rollback are all configuration, where the baseline wrote each by hand. The price is about 43 kB gzip of JavaScript on top of react-dom, more than the whole baseline page three times over.

## Where I fought it

- Timing a render: there is no "render done" callback, so the number comes from a `useLayoutEffect` that forces layout and writes into a ref'd element, to avoid a second render for the stat itself.
- The edit dialog: native `<dialog>` with `defaultValue` inputs needs a `key` per card so the fields reset, and the save handler reads the DOM rather than state.
- Drag and drop: the hover class is toggled imperatively on `currentTarget`, since putting it in state would re-render the column on every `dragover`.
- Focus after a keyboard move: React moves the node with `insertBefore`, which drops focus, so the baseline's restore-by-id stays.
- The inline theme script and the `<title>` stay in each HTML file: a component runs too late for the first, and React 19's hoisted `<title>` would duplicate the second.
- Toasts still come from the baseline's `toast.js`; a React version is a context, a portal and a reducer for the same twenty lines.
- The posts app's URL: the baseline keeps the search in `?q=` of the page URL and the route in the hash; with a hash router everything lives after `#`, so the page converts an incoming `?q=` once and the debounced search writes the hash with `replace`. The title and the route announcer are a small hook, since React Router does not own `document.title`.
- The grid's worker answer and the new row set must land in one batch: a new, shorter row set rendered against the old order indexes past the end, so the handler resets the order with the rows and the render skips a missing row.
- The guarded route checks the session cookie in the component and redirects with `location.replace`, as the baseline does; a loader would do the same without the first render, but then the whole app moves to data mode.
