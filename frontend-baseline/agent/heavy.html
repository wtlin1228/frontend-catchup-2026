Pattern 24 of 24: agent-ready UI

Every action is a tool

Six actions, each written once as a named function with a JSON schema: the buttons call it, the WebMCP registry gets it, and the console on the right calls it the way an in-browser agent would, by name with JSON arguments that are checked against the schema first. The console exists because no shipping browser exposes document.modelContext by default; it is the agent you can run today. Frameworks with agent-facing hooks would derive the same registry from their forms, actions and server functions.
