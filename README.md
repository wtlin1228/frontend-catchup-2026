# Frontend Baseline

A framework-free reference for a frontend framework survey. Twenty-four patterns that frameworks compete on, each as a **light** page (the floor: the smallest honest version) and a **heavy** page (the ceiling: what a product needs within a year), written in plain HTML, CSS and JavaScript. Port the pages to a framework, run one command, and read the numbers next to the baseline's.

## Start here

| Command | What it does |
|---|---|
| `pnpm install` | Install (Node 22 and pnpm; `corepack enable` picks the pinned pnpm) |
| `pnpm dev` | Dev server with the mock API at http://localhost:5173 |
| `pnpm build`, `pnpm preview` | Production build in `dist/`, served with the same mock API |
| `pnpm check` | Build, then check every page's structure, links, assets and sitemap (no browser) |
| `pnpm verify` | Build, check, then open every page and run every flow in headless Chrome |
| `pnpm weight` | Shipped bytes per page from the last build |
| `pnpm compare` | Build and measure the baseline and every port, write [docs/results.md](docs/results.md) (`--lighthouse` adds Lighthouse) |

The browser commands need Chrome (`/usr/bin/google-chrome` or `CHROME_PATH`) and, once, `cd tools/smoke && pnpm install`; they live in a separate package so the baseline's own dependency count stays honest.

Each pattern is a directory with `light.html` and `heavy.html`; the hub at `/` lists them with one line each, and [docs/patterns.md](docs/patterns.md) has the rationale. The light page measures what a framework costs before it helps (bytes, files, concepts); the heavy page measures how it holds up (state, errors, caching, keyboard, load, cleanup).

## How a comparison works

1. Read the framework's sheet in `docs/`.
2. Port pages into `impl/<name>/`, keeping the URLs, element ids, mock API and stylesheet (copy `impl/svelte` as the template; its `compare.config.json` tells the tooling where the page files are).
3. Run `pnpm compare`. It builds every implementation, weighs the pages, opens them, runs the flows and the on-page measurements, and writes the tables to `docs/results.md`.
4. Verify the parts no script covers with [docs/verify.md](docs/verify.md).
5. Write what the framework decided for you and where you fought it in the sheet and the port's README; the numbers stay in `docs/results.md`.

## Infrastructure, not framework

The dependencies are a build tool and three libraries, none of them a UI framework:

| Dependency | Role |
|---|---|
| Vite 8 | Dev server, bundling, multi-page build (Rolldown underneath) |
| three.js | 3D engine for the scene pages |
| marked | Markdown parser for the content pipeline |
| @fontsource-variable/roboto | Self-hosted font |

Four scripts stand in for what meta-frameworks ship, so every port can keep them and stay comparable: `scripts/html-partials.js` (build-time includes and CSP hashes), `scripts/mock-api.js` (posts, likes, contact, upload, login, status, server-sent events, RPC, a sync log, HTML fragments, error reports, CSRF, Server-Timing, the app-shell rewrite), `scripts/build-content.mjs` (Markdown to pages, index, search index, RSS, sitemap) and `scripts/gen-images.mjs` (image pipeline and app icons). Generated files (`public/images`, `content/`, feed, sitemap, icons) are git-ignored and rebuilt before `dev` and `build`.

`src/lib/` is the part every framework replaces, a few hundred lines, most of it lifecycle and cleanup. When a framework makes one of these files unnecessary, that is a finding worth writing down.

| File | Stands in for |
|---|---|
| `dom.js` | Rendering: `h()`, `svg()`, `mount()` |
| `store.js` | State: observable store, `withHistory` (undo/redo), `select` (derived) |
| `router.js` | Client routing: params, query, an AbortController per navigation, cleanup hooks, announcements |
| `api.js` | Data layer: fetch wrapper, cache with TTL, `prefetch`, `invalidate`, `HttpError` |
| `rows.js` | Shared data code that also runs in a worker |
| `rpc.js` | Server functions: batching, deduplication, live subscription |
| `sync.js` | Local-first: outbox, versions, conflicts, change feed |
| `morph.js` | DOM morphing and HTML parsing for server-rendered fragments |
| `agent.js` | WebMCP tool registration, feature-detected, with the local registry, schema check and `callTool` the agent console uses |
| `elements.js` | Components: `<relative-time>` custom element with connect/disconnect lifecycle |
| `toast.js`, `theme.js`, `i18n.js`, `auth.js` | App-wide services (context and providers in frameworks) |

## Working on it

- **Add a page to a port:** create the files named by the port's `compare.config.json` (`pageFiles` templates), add it to the port's hub, then `pnpm compare --only <name>`; the baseline's checks and flows run against it automatically because the URLs and ids match.
- **Add a port:** copy `impl/svelte/`, change `package.json`, `vite.config.js` (the plugin; keep the `@baseline` alias, `publicDir` and `mockApi()`) and `compare.config.json` (name, `versionOf`, a free `preview` port, the file templates), then `pnpm install` and `pnpm compare --only <name>`.
- **Add a pattern:** two pages under `<pattern>/`, a nav entry in `src/partials/header.html`, a hub entry in `index.html`, the pattern in `scripts/build-content.mjs` and `tools/smoke/lib.mjs`, a section in `docs/patterns.md` and `docs/verify.md`, a row in `docs/_template.md` and every sheet. `pnpm verify` tells you what you missed.
- **Keep the docs honest:** numbers live in `docs/results.md` and nowhere else; sheets and port READMEs describe, the results page measures.

## Layout

```
index.html                 hub
<pattern>/light.html       one directory per pattern, two pages each
<pattern>/heavy.html
offline/fallback.html      served by the service worker when a navigation fails
content/                   generated from content-src/ (Markdown with front matter)
src/partials/              head, header (pattern menu), footer, variant switcher, included at build time
src/pages/                 one JS/CSS module per page (<pattern>-<variant>.js), plus table.worker.js
src/lib/                   shared plumbing (see above)
src/styles/                tokens (light-dark()), base styles
src/data/gallery.json      generated build-time data
public/                    mock database, generated images, manifest, service worker
scripts/                   Vite plugins, content build, image generator, dist checker, page weights
tools/smoke/               headless-Chrome checks, flows, measurements, and the compare and verify runners (own package.json)
impl/<name>/               one port per framework, same pages and ids, own package.json and compare.config.json
docs/                      patterns, survey guide, one sheet per framework, verification guide, generated results
```
